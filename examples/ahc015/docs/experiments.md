# AHC015 実験の要点

## 採用した構成

- 方策は未来列なしの afterstate PPO、128 channel・10 residual block、potential shaping、policy `alpha=0`。
- 128 channel student はランダム初期化し、64 channel の盤面-only教師から actor 方策を3時間蒸留して開始する。
  critic は蒸留しない。以後は蒸留なし PPO を継続する。
- Kaggle T4 x2 では rollout・評価を GPU 別 process、更新を 2-process DDP/NCCL とする。global microbatch
  512を採用した。256/512/1,024 の速度差は測定誤差内だったため、512でメモリ余裕を確保する。
- PPO 継続時の学習率は、飽和に合わせて`2.5e-4`から`2.0e-4`、
  さらに`1.5e-4`へ下げる。

## 提出用探索

- epoch 483の最新best重みを探索込み提出器で直前の埋め込み重みと比較した。独立500ケースで平均
  +4,898点（SE 3,704）、さらに独立1,000ケースで平均 +3,176点（SE 2,369）と、両方で改善方向が
  再現したため採用した。
- 7手の厳密 expectimax は6手より独立1,000ケースで平均820点改善した。ターン間キャッシュ再利用と高速
  ハッシュにより、10並列で平均1.162秒、p99 1.646秒、最大1.827秒に収まった。8手は単独1ケースでも
  3.53秒かかったため使わない。
- 旧構成では88〜92手目に初手4方向・24ルール・各96 sampleのモンテカルロ探索を使い、以前の6手厳密探索
  構成との未使用1,000ケース比較で平均 +5,319点だった。
- 配置後盤面をhashで統合するDAG-MCTSへ置換した。残り12/15/20/25/30手を同一300ケースで比較し、20手が
  最良だった。最終設定（残り20手・PUCT係数700・2,560 simulation）は独立500ケースで旧モンテカルロ法
  より平均 +5,635点（SE 1,704、勝45.0%、同点20.0%、負35.0%）だったため採用する。10並列時間は
  93.6秒/500ケース、約1.87秒/ケース相当だった。
- epoch 973モデルへの更新後、他プロセスを減らした10並列環境で探索を再調整した。MCTS開始は残り
  10/12/13/14/15/16/20手を比較し、残り14〜15手が最良だったため、短い方の86〜92手目を採用する。
  simulation上限は1,024〜4,096から2,048、PUCT係数は400〜1,000から550を選んだ。上書き閾値は
  0/10/20/40/80の中で20が最高だった。末尾修正は1手より2手が+2,054点、3手は2手より+1,082点、
  4手は3手より-811点だったため3手とする。調整前（残り12手・2,560 simulation・PUCT 700・末尾2手）との
  独立500ケース比較を2回行い、採用設定はそれぞれ+1,413点（SE 895）と+1,977点（SE 1,024）だった。
  合計1,000ケースでは平均+1,695点、SE約680。最終設定の別300ケース平均は844,390点。10並列の
  実行時間は平均1.457秒、p95 1.707秒、p99 1.952秒だった。時間上限を1.35秒・1.3秒へ縮めると同一
  300ケースでそれぞれ-951点・-1,424点となったため、1.4秒を維持する。
- MCTSの未訪問手priorは、各方向へ傾けた直後の局所連結度順位とした。同一300ケースでは一様priorより
  平均 +1,241点だった。小型NN priorも検討したが、prior差の効果がこの規模に留まり、探索は既にCPU時間上限
  まで使うため、学習・追加推論コストを持ち込まず軽量priorを採用した。
- 1.9秒上限・0.2秒reserveは10並列換算で約2.07秒/ケースとなった。従来は1.8秒上限・0.2秒reserveを
  採用していたが、末尾2手修正では10並列300ケースの平均1.976秒、p99 2.457秒となった。1.4秒上限・
  0.3秒reserveへ変更すると平均1.461秒、p95 1.728秒、p99 1.907秒になり、同一ケースの平均スコアも
  128点高かったため、こちらを採用する。1.3秒まで縮めると平均423点悪化した。
- simulationごとのpathと新規ノードの行動順位を固定長配列化した。高速化後は過探索を避けるため上限を再調整し、
  同一300ケースの512/1,024/1,536/2,048/2,560/3,072/4,096比較で2,560が最良だった。
- leaf playoutを4/8/12手で打ち切り、部分連結度をその時点の味別個数二乗和で正規化するMCTSを比較した。
  300ケースでは4手がcutoff中で最良だったが、独立500ケースの4手・4,096 simulation版は終局playout版より
  平均 -1,966点（SE 1,458、勝23.4%、同点48.6%、負28.0%）だった。8手版も300ケースで終局版を
  323点下回ったため、打ち切りなしを維持する。cutoff実装は`--mcts-rollout-depth`で実験可能な形で残す。
- 60〜79手目だけ短期playout MCTSを追加し、80〜92手目は従来の終局playoutを維持する三段構成も試した。
  深さ6/8/10、開始60/65/70、早期128〜2,048 simulation、上書き閾値20〜1,000を比較した。10手・
  512 simulation・閾値100は独立300/500/1,000ケースですべて改善方向だったが、1,000ケースの改善は
  +417点（SE 1,009）に留まった。1,024 simulation版も300ケースで+2,425点、別の1,000ケースで
  -111点と再現しなかったため採用しない。早期区間専用の設定オプションは追加実験用に残す。
- MCTS prior用の小型NNとして、各方向の味別連結成分二乗和・最大成分・成分数・空き接触辺・外周を含む
  露出辺と同味隣接辺を入力する16→16→1の共有MLP（289 parameter）を実装した。128 channel actorの方向を
  教師として256局・9,728状態を105.7秒で蒸留し、未使用状態の方向一致率は78.4%だった。80〜92手目の
  prior置換は特徴の重複計算を除いた後の300ケースで連結度prior比 +164点、60〜79手目だけの置換は
  現行比 -1,743点だった。改善が確認できないため採用せず、再学習スクリプトと`tiny-nn`オプションを
  実験用に残す。
- leaf playoutの方向列を生成した後、既知の配置rank列を固定して末尾から各方向を4通り試し、改善する方向へ
  置き換える後処理を実装した。旧モデルでは、現行の最終1手最適化に対し末尾2手を1回だけ後ろ向きに修正すると、独立
  300/500/1,000ケースですべて改善し、それぞれ平均 +406/+700/+1,509点だった。最後の1,000ケースの
  SEは689点。末尾3/4/6手は同一300ケースで -382/-1,538/-2,695点、2手を2回修正する版も別の
  300ケースで -3,208点となった。長い修正・反復はシミュレーション内でだけ判明する未来配置への過適合が
  強いため、末尾2手・1 passを採用する。さらに旧提出設定（末尾1手・1.8秒）との独立500ケース比較でも、
  1.5秒上限版が平均 +1,949点（SE 1,212）だった。最終的な1.4秒版は同一300ケースで1.5秒版と平均
  350点差に留まり、2秒制限への余裕を優先した。
- 直後1〜3配置のrank組を層化した比較では、層化単独の改善は再現しなかった。一方、直後2配置の層化と
  最終有効方向の厳密化を併用すると、厳密化単独より別々の1,000ケースで平均 +403点、+602点だった。
- 最終有効方向の厳密化は従来playoutより独立1,000ケースで平均 +1,844点（SE 740）。96 sampleは128
  sampleより別の1,000ケースで平均 +254点（SE 287）で、10並列時間を平均1.267秒から1.200秒、p99
  1.732秒から1.630秒へ短縮したため採用した。
- 固定simulation上限に加え、残時間を残りのMCTS手数で割るdeadlineで打ち切る。
- 根候補の単純playout平均を、直後の全配置rankについて決定ノードの最良平均価値を平均する1段backupへ変更した。
  固定2,048 simulationを完走する未使用300ケースでは平均+1,214点（SE 541）だった。1.4秒deadline下では
  未使用500/1,000/100ケースでそれぞれ+835（SE 590）/+250（SE 461）/-1,141点（SE 1,216）で、合計
  1,600ケースは+346点（SE約350）。効果は小さいが固定探索量で明確に改善し、平均時間も同等だったため採用する。
  決定ノード平均への縮約や従来値との0.5混合、1,024 simulation未満で従来値へ戻すゲートはいずれも改善しなかった。
  DAGを次手へ持ち越す案も300ケースで+193点（SE 1,094）に留まりp95が悪化したため、DAG自体は従来どおり
  各手で作り直す。simulation上限を1,536へ下げる案は-639点（SE 790）だったため、2,048を維持する。
- architecture非依存の高速化として、共通rank列、24ルールの全行動列、初回配置後盤面を再利用し、同じ
  suffixのルールを統合した。終端連結度は`u128` bitboard flood fillへ置換した。ランダム1,000盤面で
  旧DFSと一致し、固定100ケースのスコア配列SHA-256も変更前後で一致した。
- 同一300ケース・512 sampleの10並列ジャッジ相当時間は1.339秒から1.139秒へ14.9%短縮した。
  一方、未使用1,000ケースで512 sampleは128 sampleより平均525点低く、計算量増加による改善はなかった。
  現時点ではAVX専用実装を追加しない。
- MCTS simulationごとに初期化していた10KBのpathと末尾修正用`Vec`を再利用し、DAG nodeに対する3回の
  hash lookupをentry APIの1回へ統合した。固定2,048 simulationの100ケースは全スコアが変更前と一致し、
  10並列平均時間は2.022秒から1.955秒へ3.3%、p95は2.747秒から2.640秒へ3.9%短縮した。通常の1.4秒
  deadlineでは別の300ケースで平均-150点（SE 677）とスコア改善は確認できなかったが、最大時間は2.512秒から
  2.162秒へ短縮したため、時間超過への余裕を増やす挙動不変の高速化として採用する。
- 追加高速化で固定simulation数を増やせる場合の上限効果も調べた。未使用300ケースでは1,536から2,048へ
  増やすと-392点（SE 495）だった一方、2,048から2,560は+872点（SE 498）だった。後者は別の未使用
  500ケースでも+779点（SE 392）で、合計800ケースでは+814点（SE約308）と改善が再現した。3,072回は
  2,560回より-521点（SE 458）だったため、十分高速化できた場合の再調整先は2,560回付近である。1 workerの
  平均時間は2,048回の1.493秒に対して2,560回は1.631秒であり、同じ時間へ収めるには全体で約9.2%、現行の
  1.4秒設定へ余裕込みで収めるには約15〜20%の追加高速化が必要と見積もる。現状の3.3%短縮では足りないため、
  提出デフォルトは2,048回を維持する。

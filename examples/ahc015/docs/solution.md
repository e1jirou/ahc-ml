# AHC015 強化学習解法

## 方針

この問題は、各ターンの配置直後の盤面から4方向のいずれかを選ぶ、有限時間の確率的ゲームである。
次のキャンディーの種類は既知で、置かれる空きマスだけが一様ランダムである。

主解法には、方向を直接出力する方策ネットワークではなく、**傾けた直後の盤面
（afterstate）の価値を学習する fitted value iteration** を採用する。
各ターンで4方向の結果を正確にシミュレーションし、同じ価値モデルでまとめて評価して、最も価値が
高い方向を選ぶ。

この方式を選ぶ理由は次の通りである。

- 傾斜は決定的であり、候補も常に4個しかないため、全行動の afterstate を安く列挙できる。
- 未知なのは次の配置位置だけであり、その分布も空きマス上の一様分布として既知である。
- 選ばなかった3方向も正しい学習サンプルとして利用できる。
- 盤面の回転・反転や味ラベルの置換を、スカラー価値の対称性として自然に扱える。
- 公式スコアに直結する解析的な盤面評価をベースラインにし、ネットワークには将来分だけを
  学習させられる。
- 提出時は1ターンにつき4盤面を1回評価するだけでも動作し、余った時間は任意に探索へ使える。

PPOなどの方策勾配法も適用できるが、既知の遷移分布と全4行動を直接使えない分、この問題では
afterstate 価値学習を優先する。

## 問題の性質

最終盤面にある同種連結成分の大きさを `n_1, ..., n_k` とし、全100個中の味 `i` の個数を
`d_i` とする。整数化前の公式スコアを

```text
C(B) = sum_j n_j(B)^2
D    = sum_i d_i^2
Phi(B) = C(B) / D
```

と書く。`D` は最初に与えられる味列だけで決まり、1エピソード中は一定である。すべての同じ味が
それぞれ1成分になったとき `C(B) = D` なので、`Phi` は `[0, 1]` に収まる。

大きさ `x`, `y` の同種成分を結合すると、分子は

```text
(x + y)^2 - x^2 - y^2 = 2xy
```

だけ増える。このため、小さな塊を多数作るより、大きな塊同士を接続することが重要である。
一方、現在の連結度だけを最大化する貪欲法では、将来多く出る味の空間を塞いだり、後の傾斜で塊を
分断したりする。その長期的な差を価値モデルに学習させる。

公式得点は `round(10^6 * Phi)` だが、丸めによる差は1ケースあたり高々0.5点である。学習では
滑らかな `Phi` を目的値とし、最終評価では公式の丸めも再現する。

## 状態、行動、遷移

`B_t` を、`t` 個目を配置済みで、そのターンの傾斜前の盤面とする。

- `f_1, ..., f_100`: 最初から既知の味列
- `T_a(B)`: 盤面 `B` を方向 `a in {F, B, L, R}` に傾ける決定的操作
- `W_t^a = T_a(B_t)`: 行動 `a` の直後の afterstate
- `E(W)`: `W` の空きマス集合
- `Insert(W, x, f)`: 空きマス `x` に味 `f` を置いた盤面

Markov状態に必要なのは現在の盤面、時刻 `t`、残りの味列 `f_{t+1}, ..., f_100` である。
過去の `p_t` や最後に置かれたキャンディーの印は不要である。将来の配置番号 `p` は観測できない
ので、学習時にも入力してはならない。

afterstate `W_t` から次の状態への遷移は、`E(W_t)` から一様に選んだマスへ `f_{t+1}` を置く
ことだけである。これは公式の、行優先で番号を付けた空きマスに一様な `p_{t+1}` を指定する処理と
同じ分布になる。

100個目を置くと盤面が埋まるので、最後の傾斜では何も動かない。したがって意味のある意思決定は
`t = 1, ..., 99` の99回である。提出コードでは100回目にも固定で `F` を出力してよい。

## afterstate の価値

`V_t(W)` を、`t` 個のキャンディーを持つ afterstate `W` から、以後最善に行動した場合の
最終 `Phi` の期待値と定義する。意思決定は

```text
a* = argmax_a V_t(T_a(B_t))
```

で行う。

### Bellman 方程式

`t <= 98` では、次の配置位置について期待値を取り、配置後の4方向について最大値を取る。

```text
V_t(W) = 1 / |E(W)| * sum_{x in E(W)}
           max_a V_{t+1}(T_a(Insert(W, x, f_{t+1})))
```

`t = 99` では空きマスは1個であり、次の配置で最終盤面になる。

```text
V_99(W) = Phi(Insert(W, only_empty_cell, f_100))
```

巨大な盤面状態全体を表にした厳密DPは不可能なので、この `V_t` をニューラルネットで近似する。

### 解析的ベースラインとの差分を学ぶ

最終価値そのものではなく、現在の盤面評価からの残差

```text
G_theta(W, t, future) = V_t(W) - Phi(W)
V_hat(W) = Phi(W) + G_theta(W, t, future)
```

を学習する。最終層をゼロ初期化すれば、学習開始時の方策はちょうど `Phi` 貪欲法になる。
ニューラルネットは「今すでにできている連結」を再学習せず、将来の配置と傾斜による増減だけを
予測すればよい。

この分解は reward shaping と違って目的関数を変えない。`Phi` は全候補で必ず足し戻し、推論でも
`G_theta` 単独ではなく `Phi + G_theta` を比較する。

## 対称性の利用

問題には、味番号の `3!` 通りの置換対称性と、正方形の8通りの回転・反転対称性がある。
これらを利用して入力分布を狭める。

### 味ラベル

味の元の番号自体に意味はない。主設定では各時刻に、次に現れる時刻が早い味から canonical ID
`1, 2, 3` を割り当てる。

```text
next_i(t) = min {j > t | f_j = i}  （存在しなければ infinity）
key_i(t)  = (next_i(t), static_rank_i)
```

`key_i(t)` の昇順を canonical 順とする。これにより `t < 100` では、直後に配置される
`f_{t+1}` が必ず canonical 味1になる。

`static_rank` はエピソード開始時に `(d_i, first_i)` の昇順で決める。`first_i` は味 `i` が
味列に最初に現れる位置（存在しなければ infinity）であり、未来に現れない味同士の決定的な
tie-break に使う。元の味IDを tie-breakに使うと、味ラベルを置換した入力が同じ canonical 表現に
ならないので注意する。全く出現しない味が複数ある場合、それらのchannelはすべて0なので相互の
順序は特徴量へ影響しない。

盤面自体のIDは書き換えず、特徴量を作るときだけ盤面、最終個数、残数、未来列へ同じ写像を適用する。
次時刻の候補を評価するときは `t + 1` の写像を作り直す。モデルは再帰状態を持たないため、時刻間で
同じ物理的な味の channel が変わっても Markov 性は失われない。

動的な channel 変更が学習を不安定にする場合に備え、`(d_i, first_i)` だけで全時刻を通じて
固定する静的 canonicalization も比較対象にする。

### 盤面方向

候補 `W_t^a` を特徴量化するとき、候補を生成した方向 `a` が上向きになるように盤面を回転する。
モデルが見る盤面は常に「直前に上へ圧縮された盤面」になり、4方向の圧縮パターンを別々に学ぶ
必要がなくなる。回転は特徴量にだけ適用し、ゲーム本体の盤面は元の座標系で保持する。

上方向を固定した後にも左右反転の対称性が残る。canonical 味IDで行優先に並べた盤面と、その
左右反転のうち、辞書順で小さい方を入力にする。次時刻の4候補にも、それぞれの生成方向に応じた
正規化を独立に適用する。

この変換は価値を変えない。回転・反転しても空きマス上の一様分布、4方向の行動集合、最終スコアが
すべて不変だからである。ただし辞書順の切り替わりは不連続なので、ランダムな左右反転による
data augmentation との比較も行う。

## 入力特徴量

モデル入力は `(N, 18, 10, 10)` の `f32` tensor とする。盤面とスカラー情報を先頭15 channel、
未来列を末尾3 channelへ格納し、モデル内では別branchで処理する。

| channel | 個数 | 内容 | 値域 |
| --- | ---: | --- | --- |
| 種類別占有 | 3 | canonical 味ごとの one-hot | 0 / 1 |
| 空きマス | 1 | 空きなら1 | 0 / 1 |
| 連結成分サイズ | 3 | そのマスのキャンディーが属する同種成分サイズを `100` で割った値 | `[0, 1]` |
| ターン | 1 | 全マスに `t / 100` をbroadcast | `[0, 1]` |
| 最終個数 | 3 | canonical 順の `d_i / 100` をそれぞれbroadcast | `[0, 1]` |
| 残り個数 | 3 | canonical 順の `#{j > t : f_j = i} / 100` をそれぞれbroadcast | `[0, 1]` |
| 現在のポテンシャル | 1 | 全マスに `Phi(W)` をbroadcast | `[0, 1]` |
| 全未来列 | 3 | 相対時刻順の味one-hot | 0 / 1 |

未来列 `f_{t+1}, ..., f_100` は、相対位置 `0, 1, ...` を `10 x 10` の行優先位置へ対応させ、
canonical 味の3枚のone-hot面に格納する。以後の位置は0で埋める。この3 channelは空間的な盤面とは
みなさず、flattenしてDense branchへ渡す。残数だけでは順番の違う状態を区別できないため、既知の
未来列を省略しない。直近数個だけに切ると厳密には Markov 状態でなくなる。

連結成分サイズ面は占有盤面から導出可能だが、価値に重要な大きな塊をCNNへ直接知らせる
inductive bias として加える。`d_i` は最終スコアの分母と最終的な種類比率を表す。`p_t`、過去の
行動、新しく置かれた1個を示す印は入力しない。

## モデル

参考実装の `120 channel x 8 block`（250,801 parameter）は、AtCoder環境で本リポジトリの
提出コードを測ると約0.64秒だった。この余裕をモデル容量へ振り向け、主設定には
`144 channel x 9 block`、368,209 parameterのモデルを用いる。実行時間だけでなく512 KiBの
提出ソース上限もあるため、これ以上の拡大は量子化重みを埋め込んだ最終ソースサイズを確認してから行う。

```text
Input: (N, 18, 10, 10)

Board branch:
    ChannelSlice(0..15)
    Conv 3x3, 15 -> 144, padding 1
    ReLU
    Residual depthwise-separable block x 9:
        DepthwiseConv 3x3, 144 -> 144, padding 1
        ReLU
        Conv 1x1, 144 -> 144
        Add(skip)
        ReLU
    Global average pooling                         -> 144

Future branch:
    ChannelSlice(15..18)
    Flatten 3 x 10 x 10                            -> 300
    Linear 300 -> 144, ReLU
    Linear 144 -> 144, ReLU                        -> 144

Fusion:
    Concatenate(board, future)                     -> 288
    Linear 288 -> 288, ReLU
    Linear 288 -> 1                                -> G_theta
```

最初の畳み込みと9ブロックで受容野は `21 x 21` となり、`10 x 10` 全体を覆う。Batch
Normalization と Dropout は使わず、学習時と提出時の挙動を一致させる。未来列は同じターンの
4候補で共通なので、必要になればそのbranchの出力を1回だけ計算して再利用できる。盤面4候補は常に
batch化する。

実行時間は計測環境や行列積実装に依存するため、最終提出形のRust binaryで、特徴量生成、
4候補推論、対話I/Oを含む1ケース全体を再計測する。制限へ収まらない場合にだけ、channel数を
`144 -> 120`、block数を `9 -> 8` として実測済みの標準モデルへ戻す。逆に余裕があっても、
モデルを大型化するかは固定seed上のスコア改善と学習時間を含めて判断する。

## 学習データの生成

### 公式分布のシミュレーション

各エピソードで `f_t` を独立な `Uniform{1,2,3}` から100個生成する。各ターンでは現在の空きマス
から一様に1マス選んで配置する。評価用の再現性が必要な経路では、公式と同様に一様な整数 `p_t` を
生成し、行優先の `p_t` 番目の空きマスへ変換する。

学習seedと評価seedは分離する。味列は最初から方策へ見せてよいが、将来の配置乱数は絶対に見せない。

### rollout と replay buffer

1. 配置後の `B_t` から4方向すべての `W_t^a` を作る。
2. 4候補すべてを replay buffer に保存する。
3. `Phi(W_t^a) + G_online(W_t^a)` を比較し、epsilon-greedyで実際の行動を選ぶ。
4. 次のキャンディーをランダムな空きマスへ配置して続行する。

`epsilon` は例として `0.20` から `0.02` へ減衰させる。完全ランダム方策だけで収集すると、学習後の
方策が訪れる良い盤面が不足するため、モデル更新と新しい rollout を交互に行う。

buffer には正規化前の盤面、時刻、味列またはepisode ID、候補を生成した方向を保存する。盤面は
100個の `u8` のまま保持し、batch生成時にだけ `f32` 特徴へ展開する。時刻を10程度のbucketに分けて
均等sampleすると、特定の時期に学習が偏りにくい。

## Bellman target と更新

学習サンプル `(W, t, f)` について、空きマスを `K` 個、一様かつ重複なしにsampleする。
空きマスが16個以下なら全列挙し、それ以外ではまず `K = 8` とする。

`t <= 98` の各sample位置 `x` に対して次の処理を行う。

```text
B'       = Insert(W, x, f_{t+1})
W'_a     = T_a(B')                              for all a
a*       = argmax_a [Phi(W'_a) + G_online(W'_a)]
z_x      = Phi(W'_{a*}) + G_target(W'_{a*})
y_abs    = average_x z_x
y        = y_abs - Phi(W)
```

行動選択を online network、評価を遅れて更新する target network に分ける Double-DQN 型のtargetで、
最大値による過大評価を抑える。次候補の特徴量では、時刻を `t + 1` に進め、味の動的写像も
`t + 1` 用に作り直す。

`t = 99` ではネットワークをbootstrapせず、最後の1個を唯一の空きマスへ置いた盤面から

```text
y = Phi(final_board) - Phi(W)
```

を直接計算する。近似器の誤差で `y_abs` が範囲外へ出た場合は、真の値域である `[0, 1]` へclipして
から残差へ変換してよい。

初期値の目安は次の通りである。

- loss: Huber loss
- optimizer: AdamW、学習率 `3e-4`
- batch size: 現行128、次の比較候補512
- target network: 1,000 updateごとにhard update
- replay buffer: 20万〜100万 afterstate
- gradient clipping: global norm 1〜5

終盤から価値を伝播させるため、最初は `t >= 80` を多めにsampleし、`60, 40, 20, 1` と開始時刻を
前へ広げる curriculum が考えられる。また、rolloutで実際に選ばれた afterstate については、
最終結果を使う Monte Carlo target

```text
y_MC = Phi(final_board) - Phi(W)
```

も正しい教師になる。学習初期には `y = beta * y_MC + (1 - beta) * y_Bellman` と混ぜ、`beta` を
`0.5` 程度から0へ下げると、1-step backupだけより序盤へ信号を伝えやすい。未選択候補には
Monte Carlo targetを流用できない点に注意する。

### 現在の到達点と80万へ向けた学習改善

10時間のhard update版は、学習とbest選択に使っていない2,000ケースでfloat平均607,344、Rust
int8平均612,505となった。`Phi` 貪欲法の平均348,713からは大きく改善したが、目標とする平均
800,000までは約19万点の差がある。固定512ケースの評価も、update 19,000の平均600,951から
20,000の433,044へ落ち、22,000で606,132へ戻るなど振動が大きい。したがって、単純に同じ設定で
学習時間だけを延ばすより、教師信号とデータ分布を改善する必要がある。

優先順位は次の通りとする。

1. **1 updateで見る軌跡の多様性を増やす（検証済み・不採用）。** `batch_size = 512`、
   `rollout_episodes = 128`、replay 100万件、`updates_per_iteration = 25` を試し、hard updateまでの
   学習sample数を現行と揃えた。後述の2時間比較で悪化したため、この組合せは採用しない。
2. **終盤の低bias教師（再挑戦は後回し）。** 残り5〜6個なら、配置を平均、行動を最大とする
   expectimaxを終端まで計算できる。初回は計算量を抑えて `placed >= 96`（残り4個以下）の全afterstateへ
   厳密な期待最終価値を付ける。教師値は1-step/MC targetより優先し、batchの50%を教師付き終盤標本、
   残りを通常replayとする設定を10時間hard版bestから2時間fine-tuningした。教師lossは下がったが独立平均が
   元モデルより38,848点悪化したため、この実装と設定は棄却した。expectimax自体ではなく終盤への過度な
   分布偏りが原因の可能性はあるが、再検証は後回しとする。将来再開するなら教師比率5〜10%、learning rate
   `1e-4`以下で破壊的忘却を抑える。
3. **探索によるpolicy improvementをofflineで行う（初回設定は不採用）。** 現方策が訪れた配置直後状態について、4個の
   初手それぞれから同じ配置乱数列を使って複数回playoutし、最終公式スコアの平均で候補を順位付けする。
   同一乱数を4候補へ使う common random numbers により候補差の分散を下げる。4候補を1groupとして
   replayへ保存する。初回実験では10時間hard版を固定playout方策とし、毎iteration 8局面、各方向4本の
   playoutを生成する。終局値の絶対値には少数sample由来の共通ノイズが大きいため、同一局面4手の
   action valueを平均との差へ変換してrankingだけを補助loss（weight `0.025`）で学ぶ。通常の
   Bellman/MC lossとhard target updateは維持し、learning rate `1e-4`で2時間fine-tuningして判断する。
   独立2,000ケースでは元モデルより20,330点悪化したため、この設定は不採用とする。教師最良手と
   固定方策の一致率が平均28%しかなく、各方向4本では分散が大きすぎた可能性が高い。再挑戦するなら
   playout本数を大幅に増やしたoffline dataset上でラベル再現性を先に検証する。
4. **最適化を安定化する。** hard updateはsoft updateより良かったため維持する。一方、学習後半は
   learning rateを `3e-4 -> 1e-4 -> 3e-5` と下げ、強いcheckpoint付近を微調整する。best選択用512件
   とは別に複数のvalidation seedを持ち、単一固定集合への過適合を防ぐ。10時間版bestからoptimizerを
   リセットし、`1e-4`で2時間微調整した実験では、固定評価の標準偏差と隣接変動は従来後半より小さく
   なった一方、独立2,000件の平均は元モデルとの差-11点で実質同一だった。低LRは破壊抑制には使える
   可能性があるが、それ単独で性能を伸ばす効果は確認できなかったため、このrunは延長しない。
5. **別方式として大規模batch PPOを比較する。** 公開されたAHC015のPPO例では、batchを256から
   4,096へ増やすことで平均が約64万から約77万へ改善している。afterstate方式の改善が頭打ちに
   なった場合、`gamma = 1`、GAE、全未来列入力のPPOを有力な比較対象とする。
6. **大型teacherから提出モデルへ蒸留する。** 優先度は低めだが、提出サイズを無視した大型モデルや
   ensembleが十分強くなれば、144 channelモデルへ蒸留する。絶対価値だけでなく、同一局面の4候補を
   teacherの価値でsoftmaxした行動分布と候補間rankingを学習させる。student自身の訪問状態にも
   teacherを適用するDAgger型にし、teacherが現行モデルを大幅に上回ってから実施する。

項目1の提案設定を2時間学習した結果、独立2,000ケースの平均は456,868で、同じケース上の元の
2時間hard版513,096を56,229点下回った。固定評価でも同じ傾向だったため、このlarge-batch組合せは
不採用とし、10時間へ延長しない。ただしbatch、rollout数、replay容量を同時に変えたため、batch拡大
単独の因果とは断定しない。expectimax教師50%と4本playout教師の実験も悪化した。少数playoutによる
online教師は分散が大きいため不採用とし、平均80万へ向けた次の方針は改めて選定する必要がある。

## 提出時の処理

各ターンで次を行う。

1. `p_t` を読み、現在の空きマスを行優先に数えて `f_t` を置く。
2. `t < 100` なら4方向へ傾けた候補を生成する。
3. 各候補を味・方向について正規化し、4件の盤面特徴量を作る。
4. 4候補を1回のbatch forwardで評価する。
5. `Phi(W_t^a) + G_theta(W_t^a)` が最大の方向を出力し、必ずflushする。
6. 同値なら固定順 `F, B, L, R` で選ぶ。
7. `t = 100` はモデルを呼ばず `F` を出力する。

重みは学習後にint8量子化・圧縮し、Rustソースへ埋め込む。ただし起動時に `f32` へ展開する現在の
推論器では、量子化は主に提出サイズ削減のためである。PythonとRust、量子化前後について同一入力の
出力と4候補の順位を比較する。

### 2秒制限を使う探索案（学習改善後に実装）

144 channelモデルのAtCoder実測は1ケース約0.8秒であり、2秒制限に約1.2秒の余裕がある。まず
学習済み方策単体で平均80万へ近づけることを優先し、次のhybrid探索はその後に実装する。

提出時探索を再検討する段階では、終盤expectimaxが候補になる。`H_t(W)` をafterstateからの期待最終価値として、残りが少ないときに
次を終端まで再帰する。

```text
H_t(W) = average_{x in E(W)} max_a H_{t+1}(T_a(Insert(W, x, f_{t+1})))
H_99(W) = Phi(Insert(W, only_empty_cell, f_100))
```

最後6手の完全探索には1候補あたり最大約74万終端、最後5手なら約3万終端がある。実装時には同一盤面の
memoization、同一afterstateとなる行動の重複除去、候補のNN価値順による展開を行う。まず最後5手を
完全探索し、実測に余裕があれば6手へ広げる。公開された参加者解法にも、94ターン目までは規則方策、
最後6手を配置ノードで平均・行動ノードで最大とする全探索へ切り替える例がある。

中盤では深さを固定したexpectimaxとし、葉を `Phi + G_theta` で評価する。さらに余裕があれば、4候補の
NN評価差が小さい局面だけ、未知の配置列をsampleしたMonte Carlo playoutを追加する。4候補には同じ
乱数列を使い、平均だけでなく標準誤差も見て、明らかに劣る候補への配分を早めに止める。

interactive問題なので、各ターンで個別に上限時間を使うのではなく、開始時刻からの累積時間を管理する。
例えば探索deadlineを1.7秒に置き、I/Oと終盤処理に0.3秒を残す。探索はanytimeにし、deadline時点で
完了済みの深さまたはplayoutだけから行動を返す。ローカルとAtCoderで探索深さ別の最悪時間を測り、
安全率を含めて採用する。

## PPOとの比較

比較対象としてPPOを使う場合は、配置直後の `B_t` を入力し、4個のpolicy logitと状態価値を出す。
疎な最終報酬の代わりに

```text
r_t = Phi(B_{t+1}) - Phi(B_t)
gamma = 1
```

を使える。ここで `B_{t+1}` は、現在の行動で傾けた後に次のキャンディーが置かれた盤面である。
`t = 1, ..., 99` について和を取ると `Phi(B_100) - Phi(B_1)` となり、`Phi(B_1)` は行動に
依存しないため、元の目的と同値である。`gamma < 1` にするとこの同値性は崩れる。

ただしPPOでは、回転時に4方向のlogitも対応して置換する必要がある。また、選ばなかった行動の
決定的な結果や既知の配置分布を直接targetへ使えない。実装量に対するsample efficiencyは
afterstate方式の方が高いと予想する。

## 評価と ablation

学習に使わない固定seed集合で、少なくとも次を同じケース上で比較する。

1. 一様ランダム
2. `Phi(T_a(B_t))` を最大化する貪欲法
3. 学習済み `Phi + G_theta`
4. 必要ならPPOや探索付き方策

開発中は数千〜1万ケースで整数化前の `Phi` の平均、標準誤差、貪欲法に対するpaired差分と勝率を
測る。最終的には公式スコアの平均と200ケース合計も併記する。学習lossだけでは候補の順位性能を
判断できないので、次も記録する。

- ターンbucket別のHuber loss
- targetと予測の相関
- 4候補中の最良候補を選べた割合
- `G_theta` の平均、標準偏差、最大絶対値
- 1ターンおよび1ケースのRust推論時間
- float32版と量子化版の候補一致率、公式スコア差

優先して比較するablationは次の通りである。

| 項目 | 比較 |
| --- | --- |
| 味対称性 | 動的canonical / 静的canonical / S3ランダム置換 |
| 空間対称性 | 方向を上＋左右辞書順 / 方向を上＋ランダム反転 / D4 augmentation |
| 未来情報 | 全未来列 / 残数のみ / 直近8個＋残数 |
| 盤面特徴 | component-size面あり / なし |
| target | 1-step / Monte Carlo混合 / 全空きマス列挙 |
| モデル | channel数・block数とRust実測時間 |

## 実装時に重点確認すること

- 傾斜は全キャンディーの同時移動である。各行または列から0以外を順序を保って取り出し、指定側へ
  詰めると正しく実装できる。
- `p_t` は、直前の傾斜後盤面の空きマスを行優先に数えて実マスへ変換する。
- `B_t -> W_t -> B_{t+1}` の添字と、target入力の未来列先頭が `f_{t+1}` であることをテストする。
- `t = 99` のtargetはbootstrapせず、`t = 100` の傾斜は盤面を変えない。
- 任意盤面に味の置換と盤面のD4変換を施しても、canonical特徴と価値が一致することを単体テストする。
- PythonとRustの傾斜、連結成分、`Phi`、canonicalization、forward結果を固定fixtureで照合する。
- 対話出力では毎ターン改行とflushを行う。

## 実装順序

1. 盤面、配置、4方向の傾斜、連結成分、公式スコアを実装して単体テストする。
2. ランダム法と `Phi` 貪欲法を作り、後者が固定seed評価で改善することを確認する。
3. 特徴量と対称性の正規化を実装し、置換・回転に対する不変性をテストする。
4. 標準CNNをゼロ残差で初期化し、貪欲法と完全に同じ行動になることを確認する。
5. 終端targetと軌跡上のMonte Carlo targetで学習を開始する。
6. replay、target network、sampled Bellman backup、epsilon-greedy rolloutを追加する。
7. 固定seedでablationし、貪欲法を安定して上回る設定を選ぶ。
8. 重みをRustへ移し、量子化誤差、対話I/O、実行時間、提出サイズを確認する。

最初の達成目標は、複雑なモデルを作ることではなく、同じ評価ケース上で `Phi` 貪欲法を統計的に
安定して上回る afterstate モデルを完成させることである。特に、状態遷移、終端処理、未来列のずれ、
canonicalization、Bellman targetの添字をモデル容量より先に検証する。
